Below is our Documentation Report, detailing changes we made in our high-fidelity design and how wecame about to those changes

Prototype Overview

The high-fi prototype includes five primary screens: Dashboard Home page, Create A Reservation page, My Reservation page, Support page, and Account page. The Dashboard/Home page display labeled icon buttons that navigate to main pages for users’ purpose. The interface uses the school color scheme: orange, black, and white to maintain visual consistency and predictability. Users are able to navigate to all other screens from the homepage, allowing for ease and good visibility.

My Reservation page lists the reserved room along with their details. The features in this page include deleting a reservation room, editing room location and a link to share room information to user’s peers, and the option to rebook a room. This page can be accessed through the home page, or by selecting “My Reservation” tab on the left side of the screen

The Create A Reservation page displays the calendar view with orange blocks which represent available rooms. There are 4 dropdown menus: month, date, building, and room capacity.

The Support page provides multiple assistance features to users, including a chat bot, tutorials, FAQ, and a contact for support. Like the “My Reservation” page, we have given users the option to request assistance or support or locate through the FAQ’s list of potential and resolved issues they may need assistance on.

Design Rationale

In our final high-fidelity prototype, we intentionally preserved the overall structure and familiarity of the low-fidelity version to avoid overwhelming users with excessive changes. Our primary objective at this stage was to enhance interface visibility and reduce user confusion and through more deliberate design choices. To maintain consistency, predictability and strengthen visual recognition, we incorporated the institution’s official color palette throughout the interface. This included applying school colors to key interactive elements, such as available time slots, to improve their interpretability.



This visual theme is extended to the support page, where we introduced a new “Contact Support” tile to streamline access to assistance. We also implemented revisions to the “My Events” page, which serves as the central hub for managing reservations. Specifically, we added a delete function for past reservations, enabling users to declutter their event history as needed. Additionally, we replaced the previous red/green iconography—indicating whether event durations could be edited—with explicit textual labels. This change was made to minimize ambiguity and ensure that users can easily understand the affordances associated with each reservation.



The “Create a Reservation” page introduced in this prototype addresses several common usability issues identified in the original RIT study room reservation system. In this design, orange blocks indicate room availability, providing a clearer and more intuitive visual cue for users. Additionally, we incorporated dropdown menus for building selection and room capacity, enabling users to efficiently filter and identify rooms that meet their specific needs.



The “My Reservations” page has been updated in response to user feedback. To improve clarity, we replaced the “Add Time” label with “Edit Duration,” ensuring users more accurately understand the function. We also added an information (“i”) icon that explains why a reservation’s duration may not be available for editing in certain cases.



In the low-fidelity prototype, the “Service” column has now been replaced with “Capacity,” as “Service” did not accurately reflect any part of the reservation workflow. The updated “Capacity” column clearly indicates the maximum number of occupants allowed for each room. Additionally, an edit icon has been added to the “Location” column, enabling users to change the building associated with their reservation when necessary.

Initial Test Script


  • Thank you for joining this usability test. We are evaluating a prototype for simplifying the reservation system for study rooms at RIT library
  • Our goal is to understand how insightful and efficient the system is for students and users alike and how easy it is to use it
  • The context: You are a student who needs to book a study room for group work or individual needs
  • Instructions: Please think aloud as you complete each task
  • There are no right or wrong answers, we are testing the system, not you


    • Observation Notes From Pilot Study


  • The title of delete overlay is “delete wallace library room 1234”, could mean delete room. Minor flaw. User wished it were written ‘Delete booking for Wallace Room”
  • The participant identified there was no way to go back, unless the navigation bar is used and suggested it would it be better to have a cross button at top, or back button
  • Participants felt the UI was much better, easier to understand compared to the original website
  • In task 2, the user went to the Create A Reservation page to rebook and did not realize that the rebook feature was already in the My Reservation page
  • The user suggested that location edit icon enlarger and “Rebook” label above room detail to make it noticeable
  • Users found room capacity and building features pretty easy to locate in the “Create A Reservation” page

    Revisions

  • Through the pilot study, we observed that the task in which users had to select a specific building was not possible as the page didn’t have good labeling and visibility, in response to that we created a page in our prototype dedicated to that
  • We also removed some questions from our original post study interview, as some were repetitive in seeking user feedback
  • Remove task 11 and 12 due to lack of time for create group study reservation and notification function
